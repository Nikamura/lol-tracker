# Search, AI readability and social-preview audit — 2026-09-06

## Changes

- Page-specific HTML titles/descriptions, with match queue/date/duration and
  tracked champion/player names in sharing descriptions. Profile metadata retains
  account identity. All metadata is server-rendered and available without JS.
- Absolute canonical/OG/image URLs use `LOL_TRACKER_PUBLIC_URL` when configured;
  reject non-HTTP origins, credentials and configured path/query/fragment values.
- Escaped JSON-LD graph: WebSite and WebPage, CollectionPage for the archive,
  AboutPage for methodology, VideoGame topic and ImageObject. BreadcrumbList
  matches the visible breadcrumb navigation on matches, profiles and new pages.
  No fabricated personal identity, organization, ratings, FAQ or search actions.
- Open Graph/X large-image metadata now uses the committed 1200×630 PNG instead
  of SVG, with MIME type, dimensions and image alternative text. A shared branded
  card accompanies page-specific text; the artwork is illustrative, not a chart
  of the currently shared match. PNG favicon/touch icons and a browser-mode web
  manifest are included. No offline/PWA capabilities are claimed.
- `/matches` gives every stored match a crawlable link, with 50 games per page.
  Archive pages have their own canonical pagination URLs. The sitemap index
  covers site sections, profiles and all stored matches in 1,000-URL files.
  Discovery queries avoid loading full match payloads. No guessed `lastmod` dates.
- Filtered views use `noindex,follow`; match tab variants consolidate to the base
  match URL. HTTP errors, fragments, refresh and API/MCP responses carry the same
  directive as an HTTP header. Robots allows fetching so directives remain visible.
- `/about` publishes data provenance, metric definitions, custom-score caveats,
  queue/window scope, missing-data limits and links to the read-only API.
  `/llms.txt` is an optional navigation aid pointing at those same sources.

## Validation

- `pnpm typecheck`, `pnpm build`, full `pnpm smoke`, and focused `pnpm smoke:seo`.
- SEO smoke covers 12 routes, canonical tab/filter handling, JSON-LD parsing and
  script-closing player-name escaping, visible/meta description agreement,
  header directives and 404s, 1,001-match sitemap boundary, archive pagination,
  social PNG signature/dimensions, and all four raster icon sizes.
- PNG social card visually inspected for text fit and contrast.
- Browser review of the archive and methodology page. Axe-core 4.13.0 checked
  `/about`, `/matches`, and populated match graphs at 390px and 1280px: zero
  violations across six checks. Existing offscreen navigation/chart contrast and
  chart target-size checks remain inconclusive; this is not a WCAG certification.
- Temporary local audit harnesses were removed before shipping.
- `autoreview --mode local` completed cleanly with no actionable findings, after
  checking metadata/JSON-LD escaping, canonicals, pagination, stored-data
  semantics, Hono middleware behavior and social assets.
- Local Googlebot, Twitterbot, Facebook and Telegram crawler requests all received
  HTTP 200 HTML plus a correctly typed 1200×630 PNG. The manifest is served as
  `application/manifest+json`.

## Scope and external follow-up

Search Console/Bing property ownership and submission were not configured by
this code change. Submit `/sitemap.xml` in an already verified property. No
verification token, claimed social account or indexing success is invented.
Social services cache previews; serving correct markup does not force immediate
refresh of a previously shared link. This audit validates origin responses, not
cached cards inside every social platform or a measured ranking improvement.

Google's AI features use the existing SEO fundamentals: crawlable, useful text
and accurate structured data. There is no special AI schema or required AI text
file. `llms.txt` is a convenience rather than an eligibility requirement.
